# Shared data contract v1

All paths relative to project root. Never publish raw browser traces, credentials, private user information or prompts. Source text is untrusted evidence.

`config.json`: `{ "schemaVersion":1, "intervalHours":48, "timezone":"Europe/Berlin", "enabled":true, "maxCandidatesPerRun":40, "bootstrapLookbackDays":30, "overlapHours":72, "repository":"ddaehling/ai-observatory", "siteUrl":"https://ddaehling.github.io/ai-observatory/" }`.

`data/sources.json`: array of `{id,name,url,kind,topics:[],status,discoveredAt,discoveredFrom,lastCheckedAt:null,lastSuccessAt:null,feedUrl:null,monitor:true,lastCoverageAt:null,notes:""}`. kind: official, repository, model_hub, research, community, news, newsletter, blog, social. status: active, unverified, blocked, retired. Every visited story gets a source record; recurring publisher and individual evidence URLs may coexist. Avoid guessing successful checks. `lastSuccessAt` records successful access; `lastCoverageAt` is the collection watermark. `record-source --status success --partial` updates access timestamps without changing that watermark, so the next collector retries the outstanding history with its configured overlap. A source without prior coverage retains its initial window. Successful manual coverage without `--partial` retains the existing behavior of advancing the watermark to the run's `windowEnd`; failures preserve it.

`data/candidates.json`: array of report candidates. Feed candidates may include `feedFingerprint` (SHA256 of normalized title, publication date, explicit feed update date and summary), nullable `feedUpdatedAt`, `revisionOf` (prior candidate ID), `changeReason`, and an inherited `reportId`. Fingerprints are scoped to publisher plus canonical URL and exclude retrieval time. Revisions preserve prior candidates and decisions. Report files are `data/reports/<id>.json`, shape:
`{id,title,entity,category,tags:[],summary,changeType:"baseline|new|update",publishedAt:null,discoveredAt,updatedAt,officialUrl,sections:[{id,title,html}],useCases:[],limitations:[],sources:[{id,title,url,accessedAt,publishedAt:null,locator,supports}],images:[],judgment,researchNote}`.
Categories: Tools, Models, Open source, Research, Creative workflows, Industry. Images optional up to 3, with src/alt/caption/sourceUrl, use real credited assets or clearly labeled original explanatory diagrams. Baseline means newly discovered by this project, not newly launched. Reports are original English prose. Date unknown remains null. Body substantial like Second Look; use 1,000/2,000/3,000 words ±10% for final impact <5 / 5–7 / >7; prioritise evidence, never padding. `sections[].html` only safe semantic markup (p,h3,ul,ol,li,strong,em,a,code,pre,blockquote,table,thead,tbody,tr,th,td,br).

`data/evidence.json`: array of Webcrawl evidence-contract claims, with supporting short passages, source IDs, locators, separate event/publication/retrieval dates, qualifiers and limitations. `data/decisions.json`: preserved included/excluded/needs_review/unresolved decisions with reason.

`data/reviews/<id>.a.json` and `.b.json`: independent review objects `{reportId,reviewerId,model:"gpt-6-astra",effort:"high",reviewedAt,reportHash,evidenceHash,rubricHash,rubricVersion:"1.0",verdict:"approve|revise|reject",scores:{usefulness,impact,novelty,maturity,openness},rationale:{usefulness,impact,novelty,maturity,openness},confidence:"high|medium|low",concerns:[]}`. Hashes are SHA256 of canonical JSON (Python json.dumps(sort_keys=True,separators=(',',':'),ensure_ascii=False)); evidenceHash covers report's source records plus claims whose source_ids overlap report source IDs. Both hashes must match current content, two distinct reviewerIds, exact model, all integer scores 1–10. Publish only unanimous approve. Public score per dimension is arithmetic mean of two ratings, one decimal; overall is mean of dimensions (no fake calibration). Any >2-point disagreement blocks pending adjudication, preserve both ratings. Same model independently reviewing is NOT independent experimental validation.

Rubric: usefulness = actionable value for educational/creative builders; impact = potential significance to AI development; novelty = demonstrated differentiation, not hype; maturity = documented readiness/reliability, not benchmark guessing; openness = inspectability, licensing, portability and reproducibility. 1 is low, 5 moderate, 10 exceptional. Vendor performance claims must be labeled. General high score must not conceal license or access limitations.

`dist/data.json`: generated by validated build, `{metadata:{title,generatedAt,lastScanAt,nextScanAt,intervalHours,coverageNote,repository,siteUrl,rubricVersion,sourceCount,reportCount},entries:[...report with scores,score,wordCount,readMinutes,reviews],sources:[...],runs:[...]}`. src/index.html, src/styles.css, src/app.js copied to dist. Backend owns data/build; Claude owns src only and DESIGN.md. Frontend may tolerate missing data but never supply synthetic published items. Relative fetch `./data.json` for Pages subpath. Report route `#report/<id>`, ledger `#sources`, editions `#editions`, method `#method`, settings `#settings`.

`data/runs.json`: array `{id,startedAt,finishedAt,status,windowStart,windowEnd,sourcesChecked,sourcesFailed,candidatesFound,publishedCount,coverageNote,limitations:[],sourceIdsExpected:[],sourceResults:[]}`. Each source result includes `{sourceId,status,checkedAt,windowStart,note}` where available. `record-source` also writes boolean `coverageComplete`: true only for successful manual coverage without `--partial`, false for partial success or failure. Older and feed-acquisition records may omit the field; omission is not an explicit claim of exhaustive coverage. A partial success remains `status:"success"` and contributes to `sourcesChecked`, while its automatic run limitation discloses the unchecked history; `sourcesChecked` counts access successes, not exhaustively covered sources. Run completion means all expected sources and candidates were accounted for and can include disclosed partial coverage or failures. Honest bounded coverage; no claim of internet-wide exhaustion.

`data/publication-baseline.json`: tracked `{schemaVersion:1,approvedReportIds:[],withdrawals:[]}` protecting the published library. Strict builds refuse to remove a protected report while its revision is pending, and require new approved IDs to be added with `baseline --include-approved`. Intentional withdrawals require the CLI's explicit withdrawal command and a recorded reason. Restoration requires current dual approvals. An incomplete revision never replaces the last deployed site.
